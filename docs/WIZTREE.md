# WizTree integration

[WizTree](https://diskanalyzer.com/) reads the NTFS Master File Table directly, so a full drive takes
seconds instead of minutes. We use only its command-line CSV export; its window never needs to be opened.

## Getting it

```powershell
python scripts/get_wiztree.py            # downloads wiztree_4_33_portable.zip → tools/wiztree/
python scripts/get_wiztree.py --url https://diskanalyzer.com/files/wiztree_4_40_portable.zip   # newer version
```

`tools/` is git-ignored on purpose: WizTree's EULA forbids copying or bundling it, and it is **free for
personal use only**. Business use needs a supporter code from Antibody Software. Set `SA_WIZTREE_EXE` to
point at an existing install instead.

Portable vs installed makes no difference to us: both accept the same command line.

## How we run it

`storage_analyzer/scanner/wiztree.py` writes `data/exports/run_wiztree.ps1`:

```powershell
Start-Process -FilePath 'tools\wiztree\WizTree64.exe' -ArgumentList '"C:" /export="data\exports\wiztree_C.csv" /exportfolders=1 /exportfiles=1 /admin=1' -Wait
Start-Process -FilePath 'tools\wiztree\WizTree64.exe' -ArgumentList '"D:" /export="data\exports\wiztree_D.csv" /exportfolders=1 /exportfiles=1 /admin=1' -Wait
```

and launches that script **once, elevated** (`Start-Process powershell -Verb RunAs -Wait`). That is the
single UAC prompt you see per scan. Without `/admin=1` (`scan --no-admin`) WizTree falls back to a normal
directory walk: no prompt, but slow.

## CSV format (4.33)

```
Generated by WizTree 4.33 10/25/2026 9:47:35 PM (You can hide this message by making a donation)
File Name,Size,Allocated,Modified,Attributes,Files,Folders,DRIVECAPACITY,FREESPACE,USEDSPACE,RESERVEDSPACE
"C:\",334634524672,318618927104,2026/10/25 21:22:01,0,1126770,332737,449324056576,100489453568,348834603008,6129823744
"C:\Users\",...
"C:\Users\chamu\file.txt",1234,4096,2026/01/02 03:04:05,32,0,0
```

- Folders end with `\`; `Files`/`Folders` are recursive counts; `Modified` is the newest time inside.
- Only the drive-root row has the four capacity columns.
- `Allocated` is bytes on disk (what you get back when deleting); `Size` is logical bytes.
- Dates are local time, `YYYY/MM/DD HH:MM:SS`.
- The file is UTF-8 with BOM. C: produces ~240 MB / 1.5 M lines; parsing + import takes ~10 s.

Odd entries you will see: `C:\$MFT.`, `C:\System Volume Information\{guid}.` (trailing dot = WizTree's way of
naming NTFS metadata files). The `ntfs-meta` rule marks them keep.

## If the export fails

- No CSV produced → the UAC prompt was declined. Re-run `scan`.
- Non-NTFS drives (exFAT USB sticks) work but slowly; fixed NTFS disks are the default scan set.
- WizTree changed its CSV? Update `parse_csv` in `scanner/wiztree.py`; the header line is read by name, so
  added columns are harmless.
